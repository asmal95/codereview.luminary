# Анализ безопасности плагина codereview.gpt

## 🔍 Общая оценка безопасности

**Версия:** 0.3.0  
**Дата анализа:** 2024

---

## 1. 🔴 УТЕЧКА ДАННЫХ

### ✅ **НЕТ утечек данных на сторонние серверы (кроме OpenAI)**

**Что отправляется:**
- **Код из PR/MR** → отправляется в **OpenAI API** (api.openai.com) через библиотеку `chatgpt`
- **API ключ пользователя** → используется для аутентификации в OpenAI API
- **Описание PR/MR** → отправляется в OpenAI как контекст
- **Заголовок PR/MR** → отправляется в OpenAI

**Что НЕ отправляется:**
- ❌ Нет отправки данных на серверы разработчиков расширения
- ❌ Нет аналитики или телеметрии
- ❌ Нет отправки данных на сторонние сервисы (кроме OpenAI)

**Куда отправляются данные:**
1. **OpenAI API** (`api.openai.com`) — через библиотеку `chatgpt`
   - Отправляется весь код из PR/MR
   - Отправляется описание и контекст PR/MR
   - Используется HTTPS для шифрования в transit

2. **GitHub/GitLab** — только для **получения** patch-файлов:
   - `https://patch-diff.githubusercontent.com/raw/...` (GitHub)
   - `{gitlab_url}/-/merge_requests/{id}.patch` (GitLab)
   - Это **входящие** запросы, данные не отправляются

### ⚠️ **КРИТИЧЕСКИЙ МОМЕНТ:**
**Весь код из PR/MR отправляется в OpenAI**, что означает:
- Код может быть использован OpenAI для обучения моделей (в зависимости от настроек аккаунта)
- Код хранится на серверах OpenAI (временно или постоянно)
- Для конфиденциального/проприетарного кода это **небезопасно**

### 🔐 **Хранение данных локально:**
- **API ключ** → хранится в `chrome.storage.sync` (синхронизируется между устройствами пользователя)
- **Результаты ревью** → хранятся в `chrome.storage.session` (только для текущей сессии браузера)
- Данные хранятся **локально**, не отправляются разработчикам

## 2. 🔗 ВНЕШНИЕ ИНТЕГРАЦИИ

### Основные интеграции:

#### 1. **OpenAI API** (обязательная)
- **Библиотека:** `chatgpt` версия `^5.1.3`
- **Эндпоинт:** `api.openai.com` (через библиотеку)
- **Назначение:** Анализ кода и генерация ревью
- **Данные:** Весь код из PR/MR, описание, заголовок
- **Аутентификация:** API ключ пользователя (хранится локально)
- **Протокол:** HTTPS

#### 2. **GitHub** (для получения данных)
- **Эндпоинт:** `https://patch-diff.githubusercontent.com/raw/...`
- **Назначение:** Получение patch-файла PR
- **Данные:** Только входящие запросы (GET)
- **Протокол:** HTTPS

#### 3. **GitLab** (для получения данных)
- **Эндпоинт:** `{gitlab_url}/-/merge_requests/{id}.patch`
- **Назначение:** Получение patch-файла MR
- **Данные:** Только входящие запросы (GET)
- **Протокол:** HTTPS
- **Поддержка:** SaaS (gitlab.com) и self-hosted инстансы

### ⚠️ **Проблемы с разрешениями:**

В `manifest.json` есть **широкое разрешение**:
```json
"optional_host_permissions": [
  "https://*/*"
]
```

Это разрешение позволяет расширению делать запросы к **любым** HTTPS-сайтам. Хотя в коде используются только указанные выше эндпоинты, такое широкое разрешение создает потенциальный риск при обновлении расширения.

**Рекомендация:** Ограничить разрешения только необходимыми доменами.

## 4. 🔒 АНАЛИЗ КОДА НА УЯЗВИМОСТИ

### ✅ **Положительные моменты:**

1. **Нет явных утечек данных:**
   - Нет отправки данных на сторонние серверы (кроме OpenAI)
   - Нет аналитики или телеметрии
   - Данные хранятся локально

2. **Использование безопасных API:**
   - `chrome.storage.sync` для API ключа (шифруется Chrome)
   - `chrome.storage.session` для кэша (только сессия)
   - HTTPS для всех внешних запросов

3. **Обработка ошибок:**
   - Есть try-catch блоки
   - Ошибки обрабатываются и показываются пользователю

### ⚠️ **Потенциальные проблемы:**

1. **console.log с чувствительными данными:**
   ```javascript
   // Строка 48 в popup.js
   console.log(options); // Может логировать API ключ!
   ```
   **КРИТИЧНО:** Это может выводить API ключ в консоль браузера, что является утечкой данных.

2. **Широкие разрешения в manifest.json:**
   - `"optional_host_permissions": ["https://*/*"]` — слишком широкое разрешение
   - Позволяет делать запросы к любым сайтам

3. **Нет валидации входных данных:**
   - URL парсится без валидации
   - Patch-файлы загружаются без проверки размера
   - Нет защиты от XSS в отображаемом HTML

4. **Использование innerHTML:**
   ```javascript
   document.getElementById('result').innerHTML = converter.makeHtml(...)
   ```
   - Потенциальный риск XSS, хотя используется `showdown` для конвертации Markdown
   - Рекомендуется использовать `textContent` или санитизацию HTML

5. **Нет защиты от CSRF:**
   - Запросы к OpenAI не защищены от CSRF (хотя это может быть не критично для API ключей)

## 8. 📝 ЗАКЛЮЧЕНИЕ

Плагин **не отправляет данные разработчикам**, но **отправляет весь код в OpenAI API**. Это критично для конфиденциального кода. 

**Основные риски:**
1. Код может быть использован OpenAI для обучения
2. Код хранится на серверах OpenAI
3. Есть технические уязвимости (console.log, широкие разрешения)

**Для безопасного использования:**
- Использовать только для публичного кода
- Регулярно обновлять зависимости
- Исправить критические уязвимости (console.log, разрешения)
- Рассмотреть self-hosted альтернативы для конфиденциального кода
