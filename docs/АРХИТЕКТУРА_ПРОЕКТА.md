## Общее описание

**codereview.luminary** (ранее codereview.gpt) — это Chrome/Chromium расширение для автоматического code review с использованием AI (ChatGPT-совместимые API). Расширение работает на GitHub и GitLab (SaaS и self-hosted).

### Основные функции:
1. **Code Review** — анализ Pull Request (GitHub) и Merge Request (GitLab) с помощью AI
2. **AI Chat** — объяснение выделенного текста через чат-интерфейс с возможностью вести диалог

### Технологический стек:
- **Manifest Version**: 3 (современный стандарт Chrome Extensions)
- **Frontend**: Vanilla JavaScript (ES6+), CSS3 с TailwindCSS
- **Build System**: Webpack 5
- **API Integration**: OpenAI-compatible REST API с поддержкой Server-Sent Events (SSE)

## Компоненты системы

### 1. Background Script (`src/background.js`)

**Назначение**: Service worker, работает в фоне и управляет глобальной логикой расширения.

**Основные обязанности**:
- **Контекстное меню**: Создает пункт "Объяснить с помощью AI" при правом клике на выделенный текст
- **Обработка кликов**: Управляет кликами по иконке расширения
- **Маршрутизация сообщений**: Передает сообщения между content script и options page
- **Streaming proxy**: Проксирует streaming HTTP запросы к AI API (чтобы обойти CORS); поддерживает отмену запроса через `AbortController` по команде из content script
- **Работа с хранилищем**: Управляет `chrome.storage.sync` и `chrome.storage.session`
- **Fetch патчей**: Загружает .patch и .diff файлы от GitHub/GitLab

**Ключевые функции**:
```javascript
// Создание контекстного меню
chrome.runtime.onInstalled.addListener()
chrome.contextMenus.onClicked.addListener()

// Обработка кликов по иконке
chrome.action.onClicked.addListener()

// Обработка сообщений
chrome.runtime.onMessage.addListener()
  - getApiKey: получение настроек
  - getCache / setCache / removeCache: работа с кешем
  - fetchPatch: загрузка diff файлов

// Streaming API proxy
chrome.runtime.onConnect.addListener()
  - streaming-api: порт для SSE запросов
  - streamRequest: URL, headers, body → fetch(..., { signal }) → разбор SSE/plain JSON → chunk/done/error/aborted
  - abortStream: прерывание текущего fetch и чтения тела ответа (сообщение `type: 'aborted'` в content script)
```

**Debounce механизм**: Предотвращает дублирование запросов (например, двойной клик контекстного меню) с задержкой 1500мс.

**SSE Parsing**: Умеет парсить:
- Стандартный SSE формат (`data: {...}`)
- Plain JSON формат (для Ollama и подобных)

### 3. Options Page (`src/options.js` + `public/options.html`)

**Назначение**: Страница настроек расширения, открывается в отдельной вкладке.

**Конфигурируемые параметры**:

#### API Settings
- `openai_apikey`: API ключ OpenAI или совместимого сервиса
- `api_base_url`: Base URL API (по умолчанию: https://api.openai.com/v1)
- `model`: Название модели (gpt-4, gpt-3.5-turbo и т.д.)
- `api_timeout`: Таймаут в секундах (по умолчанию: 300с)
- `max_tokens`: Максимальная длина ответа (по умолчанию: 8192)
- `temperature`: Креативность ответа 0.0-2.0 (по умолчанию: 0.7)

#### Prompt Settings
- `system_prompt`: Системное сообщение (роль AI)
- `review_prompt`: Инструкции для code review (переменная `{title}`)
- `final_prompt`: Финальный запрос на подведение итогов
- `explain_prompt`: Промпт для объяснения текста (переменная `{text}`)

**Функции**:
```javascript
saveOptions()    // Сохранение в chrome.storage.sync
restoreOptions() // Загрузка из chrome.storage.sync
resetPrompts()   // Сброс промптов к дефолтным значениям
```

**Хранилище**: Использует `chrome.storage.sync` (синхронизируется между устройствами пользователя).

### 4. API Client (`src/api/ApiClient.js`)

**Назначение**: Универсальный клиент для работы с OpenAI-compatible streaming API.

**Особенности**:
- **Streaming support**: Поддержка Server-Sent Events (SSE)
- **Port-based communication**: Использует `chrome.runtime.Port` для обхода CORS
- **Прерывание генерации**: возвращает `{ abort }` — вызов отправляет `abortStream` в background, где отменяется `fetch` и чтение потока
- **Timeout handling**: Настраиваемый таймаут запросов (по таймауту порт закрывается, вызывается `onError`, не `onAbort`)
- **Error handling**: Обработка ошибок с информативными сообщениями

**Метод**:
```javascript
const { abort } = ApiClient.streamRequest(
  config,
  messages,
  onChunk,
  onDone,
  onError,
  onAbort   // опционально: (accumulatedText) => void — пользователь нажал «Стоп»
);
```

**Параметры**:
- `config`: объект с `apiKey`, `baseUrl`, `model`, `apiTimeout`, `maxTokens`, `temperature`
- `messages`: массив сообщений `[{role: 'system'|'user'|'assistant', content: string}]`
- `onChunk`: callback получения чанков (вызывается с накопленным ответом)
- `onDone`: callback успешного завершения стрима
- `onError`: callback ошибки (HTTP, сеть, обрыв порта до завершения и т.д.)
- `onAbort`: callback явной отмены (тип сообщения `aborted` от background); аргумент — текст, накопленный к моменту остановки

**Возвращаемое значение**: `{ abort: () => void }` — можно вызывать сразу после старта; повторные вызовы после завершения/отмены безопасны (no-op на стороне клиента после `disconnect`).

**Поток работы**:
```
Content Script → chrome.runtime.connect() → Port Created
                    ↓
Port → postMessage({action: 'streamRequest'}) → Background Script
                    ↓
Background → fetch(API_URL, { signal: AbortController }) → Stream Reader
                    ↓
Stream → Parse SSE/JSON → port.postMessage({type: 'chunk'})
                    ↓
Content Script → onChunk() → Update UI
                    ↓
     ┌─────────────── «Стоп»: postMessage({action: 'abortStream'}) ───────────────┐
     ↓                                                                              ↓
Stream Done → port.postMessage({type: 'done'})              AbortError → {type: 'aborted'}
     ↓                                                                              ↓
Content Script → onDone() → Complete                              → onAbort() → UI
```

#### FloatingReviewWindow

**Назначение**: Окно для code review Pull Request / Merge Request.

**Ключевые методы**:
```javascript
runReview()           // Запуск процесса review
reviewPR(diffPath, context, title) // Основная логика review
getDiffPath(url)      // Определение URL для .patch/.diff
clearCache(diffPath)  // Очистка кеша
setStatus(ongoing, failed, rerun) // Обновление статуса (spinner/checkmark/error)
setReviewStopVisible(visible) // Кнопка «Стоп» только на время streaming к LLM
```

**Остановка генерации**:
- Кнопка `#review-stop-btn` («Стоп») показывается на время `ApiClient.streamRequest`; `abort()` шлёт `abortStream` в background.
- При `onAbort` частичный ответ остаётся на экране с пометкой «Генерация остановлена»; результат **не** записывается в `chrome.storage.session` (ревью не считается завершённым).
- Пока идёт любой «ongoing» статус (включая загрузку патча до стрима), `setStatus(true)` скрывает «Стоп»; она снова показывается только перед вызовом `streamRequest`.

**Поток работы**:
1. Определение платформы (GitHub / GitLab)
2. Извлечение diff URL
3. Проверка кеша (`chrome.storage.session`)
4. Загрузка .patch/.diff файла через background script
5. Парсинг патча (`parse-diff` библиотека)
6. Фильтрация (удаление lock.json, binary патчей)
7. Разбиение на чанки (максимум 15384 символов на файл)
8. Формирование промптов с подстановкой переменных
9. Streaming запрос к API (с возможностью отмены)
10. Рендеринг markdown ответа (`showdown` библиотека)
11. Кеширование результата (только при успешном `onDone`, не при `onAbort`)

**Поддерживаемые URL**:
- GitHub: `https://github.com/{owner}/{repo}/pull/{number}`
  - Diff URL: `https://patch-diff.githubusercontent.com/raw/{owner}/{repo}/pull/{number}.patch`
- GitLab: `{instance_url}/-/merge_requests/{number}`
  - Diff URL: `{mr_url}.diff`

**Кеширование**: Использует `diffPath` как ключ в `chrome.storage.session` для предотвращения повторных запросов.

#### FloatingExplainWindow

**Назначение**: Чат-окно для объяснения выделенного текста.

**Особенности**:
- **Chat history**: Хранит историю диалога `messages: [{role, content}]`
- **Context panel**: Сворачиваемая панель с выделенным текстом
- **Streaming response**: Потоковое отображение ответа
- **Остановка генерации**: на время `STREAMING` кнопка отправки переключается в красную «Стоп» (тот же `#explain-submit-btn`); вызов `abort()` из `ApiClient.streamRequest`
- **State machine**: `IDLE | LOADING | STREAMING | COMPLETED | ERROR`
- **Debounce**: Защита от повторного открытия (cooldown 2 секунды)

**Ключевые методы**:
```javascript
show(text)           // Показать окно с новым текстом
explainText()        // Отправить запрос на объяснение
clearChat()          // Очистить историю диалога
addMessage(role, content) // Добавить сообщение в историю
renderMessage(role, content, isStreaming) // Рендер сообщения
setSubmitStopAppearance(btn) / resetSubmitButton(btn) // UI «Отправить» ↔ «Стоп»
toggleContext() / collapseContext() / expandContext() // Управление context panel
```

**Поведение при остановке (`onAbort`)**:
- Частичный ответ сохраняется в `messages` (если уже есть текст); внизу ответа добавляется строка *«Генерация остановлена.»*
- Если чанков не было — пустой пузырь ассистента удаляется из DOM
- Поле `_abortExplainStream` сбрасывается в колбэках `onDone` / `onError` / `onAbort`

**Логика работы**:
1. При первом запросе — используется `explain_prompt` с подстановкой `{text}`; если вопрос пустой, добавляется дефолтный user-вопрос
2. При последующих запросах — используется упрощенный промпт с контекстом кода
3. История диалога передается в API для сохранения контекста беседы
4. При смене выделенного текста — история очищается
5. При закрытии окна — устанавливается флаг `wasHidden`, при повторном открытии история очищается

**Cooldown механизм**: Предотвращает повторное открытие окна при случайном двойном клике (2 секунды после закрытия).

## Внешние запросы и интеграции

### 1. OpenAI-compatible API

**Endpoint**: `{baseUrl}/chat/completions`

**Метод**: POST

**Headers**:
```javascript
{
  'Content-Type': 'application/json',
  'Authorization': 'Bearer {apiKey}'
}
```

**Body**:
```json
{
  "model": "gpt-4",
  "messages": [
    {"role": "system", "content": "..."},
    {"role": "user", "content": "..."},
    {"role": "assistant", "content": "..."}
  ],
  "stream": true,
  "max_tokens": 8192,
  "temperature": 0.7,
  "top_p": 1.0
}
```

**Response format** (SSE):
```
data: {"choices":[{"delta":{"content":"Hello"}}]}

data: {"choices":[{"delta":{"content":" world"}}]}

data: [DONE]
```

**Совместимость**:
- OpenAI API (https://api.openai.com/v1)
- OpenRouter (https://openrouter.ai/api/v1)
- LocalAI, Ollama, LM Studio (http://localhost:xxxx/v1)
- Любые OpenAI-compatible эндпоинты

**Особенность**: Для localhost/127.0.0.1 не требуется API ключ (используется dummy ключ "ollama").

### 2. GitHub API

**Patch URL**: `https://patch-diff.githubusercontent.com/raw/{owner}/{repo}/pull/{number}.patch`

**Метод**: GET (через background script для обхода CORS)

**Response**: Plain text в формате unified diff (unidiff)

**Извлекаемые данные**:
- Commit messages (из заголовков патча)
- Code changes (diffs)
- PR description (из DOM: `.markdown-body`)
- PR title (из `document.title`)

### 3. GitLab API

**Diff URL**: `{merge_request_url}.diff`

**Метод**: GET (через background script)

**Response**: Plain text в формате unified diff

**Извлекаемые данные**:
- MR description (из DOM: `.description textarea[data-value]`)
- Code changes (diffs)
- MR title (из `document.title`)

**Поддержка**: GitLab SaaS (gitlab.com) и self-hosted инстансы (определяется по meta тегу `content="GitLab"`).

  ```javascript
  const files = parsediff(patch);
  ```

### 1. chrome.storage.sync

**Назначение**: Синхронизируемые настройки между устройствами.

**Хранимые данные**:
```javascript

  openai_apikey: string,      // API ключ

  review_prompt: string,      // Промпт для code review

}
```

**Доступ**:
- Options page → `chrome.storage.sync.get/set()`
- Content script → через `getConfig()` (utils/config.js)

### 2. chrome.storage.session

**Назначение**: Временный кеш (очищается при закрытии браузера).

**Хранимые данные**:
```javascript

```

**Ключи**: URL .patch/.diff файла (например: `https://patch-diff.githubusercontent.com/.../pull/123.patch`)

**Логика кеширования**:
- При успешном review → сохранение HTML в session storage
- При повторном открытии PR → проверка кеша
- Кнопка "run again" → очистка кеша + новый запрос

### 3. localStorage

**Назначение**: Локальное хранилище состояния UI.

**Хранимые данные**:


**Использование**: Восстановление позиции/размера окон при повторном открытии.

## Коммуникация между компонентами

### 1. Background ↔ Content (chrome.runtime)

**Механизм**: Message passing

**Направление: Background → Content**
```javascript
chrome.tabs.sendMessage(tabId, {
  action: 'toggleFloatingWindow' | 'explainText',
  timestamp: Date.now(),
  text: string (для explainText)
});
```

**Направление: Content → Background**
```javascript
chrome.runtime.sendMessage({
  action: 'getApiKey' | 'getCache' | 'setCache' | 'removeCache' | 'fetchPatch',
  key: string,
  value: any,
  url: string
});
```

### 2. Content ↔ Background (chrome.runtime.Port)

**Механизм**: Long-lived connections для streaming

**Создание порта (Content)**:
```javascript
const port = chrome.runtime.connect({ name: 'streaming-api' });
```

**Отправка запроса**:
```javascript
port.postMessage({
  action: 'streamRequest',
  url: string,
  method: 'POST',
  headers: object,
  body: string
});
```

**Отмена запроса (Content → Background)**:
```javascript
port.postMessage({ action: 'abortStream' });
```

**Получение ответа**:
```javascript
port.onMessage.addListener((msg) => {
  if (msg.type === 'chunk') { /* новый чанк */ }
  if (msg.type === 'done') { /* нормальное завершение */ }
  if (msg.type === 'aborted') { /* отмена пользователем (или AbortError) */ }
  if (msg.type === 'error') { /* ошибка */ }
});
```

### 3. Options ↔ chrome.storage.sync

**Механизм**: Direct API calls

**Сохранение**:
```javascript
chrome.storage.sync.set({ openai_apikey: '...', ... }, callback);
```

**Загрузка**:
```javascript
chrome.storage.sync.get(['openai_apikey', ...], (items) => { ... });
```

## Нюансы и особенности

### 1. CORS Bypass через Background Script

**Проблема**: Content scripts не могут делать cross-origin запросы напрямую.

**Решение**: 
- Fetch .patch/.diff → через background script (`chrome.runtime.sendMessage({ action: 'fetchPatch' })`)
- Streaming API → через Port + background script proxy

### 2. SSE Parsing

Background script умеет парсить два формата:

**Стандартный SSE** (OpenAI):
```
data: {"choices":[{"delta":{"content":"Hello"}}]}
```

**Plain JSON** (Ollama, LM Studio):
```json
{"choices":[{"delta":{"content":"Hello"}}]}
```

**Fallback**: Если строка не начинается с `data:`, пытается парсить как plain JSON.

### 3. Stale Message Protection

Content script игнорирует сообщения старше 5 секунд:
```javascript
const messageAge = Date.now() - (request.timestamp || 0);
if (messageAge > 5000) return;  // Игнорировать устаревшие
```

**Назначение**: Предотвращает обработку задержанных сообщений после перезагрузки страницы.

### 4. Debounce Mechanisms

**Context menu debounce** (1500ms):
```javascript
if (now - lastExplainSentAt < EXPLAIN_DEBOUNCE_MS) return;
```

**Window reopening cooldown** (2000ms):
```javascript
if (timeSinceHide < 2000 && sameText) return;
```

**Назначение**: Защита от случайных двойных кликов.

### 5. Singleton Pattern для окон

```javascript
const windowInstances = { review: null, explain: null };

function getWindowInstance(type, WindowClass) {
  if (windowInstances[type] && !windowInstances[type].exists()) {
    windowInstances[type] = null;
  }
  if (!windowInstances[type]) {
    windowInstances[type] = new WindowClass();
  }
  return windowInstances[type];
}
```

**Назначение**: Гарантирует, что существует только один экземпляр каждого окна.

### 6. Dynamic Content Script Injection

При клике на иконку расширения:
1. Попытка отправить сообщение в tab
2. Если ошибка → инжект content.js через `chrome.scripting.executeScript()`
3. Ожидание сигнала `contentScriptReady` (c fallback timeout)
4. Повторная отправка сообщения

**Назначение**: Поддержка работы на страницах, открытых до установки расширения.

### 7. Patch Truncation

```javascript
if (patchPart.length >= 15384) {
  patchPart = patchPart.slice(0, 15384);
  warning = 'Some parts of your patch were truncated...';
}
```

**Лимит**: 15384 символа (~4096 токенов) на файл.

**Назначение**: Предотвращение превышения лимита токенов API.

### 8. Binary Patch Removal

```javascript
const regex = /GIT\sbinary\spatch(.*)literal\s0/mgis;
patch = patch.replace(regex, '');
```

**Назначение**: Удаление бинарных патчей (изображения, архивы и т.д.) из анализа.

### 9. Lock Files Filtering

```javascript
if (file.from.includes('lock.json')) return;
```

**Назначение**: Игнорирование package-lock.json, yarn.lock и подобных файлов.

### 10. Localhost API Key Override

```javascript
const isLocalhost = options.api_base_url?.includes('localhost') || 
                   options.api_base_url?.includes('127.0.0.1');
const apiKey = isLocalhost ? 'ollama' : options.openai_apikey;
```

**Назначение**: Для локальных API серверов (Ollama, LM Studio) не требуется настоящий API ключ.

### 11. Markdown Rendering Security

**Используемая библиотека**: showdown (v2.1.0)

**Настройки**: По умолчанию (без дополнительных опций)

**Потенциальная проблема**: XSS через markdown (если AI вернет вредоносный HTML)

**Митигация**: Ответы от AI рендерятся в изолированном контексте extension page, не в контексте веб-страницы.

### 12. Window Position Validation

При каждом показе окна:
```javascript
ensureWindowInBounds(rect)
```

**Проверки**:
- Минимальная ширина/высота
- Не выходит за пределы viewport
- Видна хотя бы частично при перетаскивании

**Назначение**: Предотвращение потери окна за пределами экрана.

### 13. State Persistence Strategy

**Review window**:
- Позиция/размер → localStorage
- Результат review → chrome.storage.session

**Explain window**:
- Позиция/размер → localStorage
- История чата → в памяти (очищается при закрытии)

**Обоснование**: 
- История чата может быть конфиденциальной → не сохраняется
- Результаты review могут быть большими → session storage (ограничение ~10MB)

### 14. Streaming Request ID

```javascript
this.streamRequestId = (this.streamRequestId || 0) + 1;
const currentRequestId = this.streamRequestId;

// В callbacks:
if (currentRequestId !== this.streamRequestId) return;
```

**Назначение**: Игнорирование ответов от старых запросов при быстром переключении между запросами.

### 15. Chat History Management

**Explain window**:
- При первом запросе: `explain_prompt` с `{text}`
- При последующих: упрощенный промпт + полная история `messages[]`

**Очистка истории**:
- При смене выделенного текста
- При закрытии и повторном открытии окна
- Вручную через `clearChat()` (если будет добавлено в UI)

### 16. Temperature & Max Tokens

**Temperature**:
- 0.0 → детерминированные ответы
- 0.7 → сбалансировано (дефолт)
- 1.0+ → креативные ответы

**Max Tokens**:
- 8192 → дефолт
- Рекомендуется уменьшить до 4096-6144 если API возвращает ошибки
- Рекомендуется увеличить до 12288+ для очень больших PR

**Влияние**:
- Temperature → стиль ответа
- Max Tokens → максимальная длина ответа (не гарантирует полный ответ)

### 17. Остановка streaming (abort)

**Background** (`background.js`, порт `streaming-api`):
- На `streamRequest` создаётся `AbortController`, в `fetch` передаётся `signal`
- На `abortStream` вызывается `abort()` у активного контроллера; при гонке «Стоп до первого байта» используется флаг `pendingUserAbort`
- Сообщение `type: 'aborted'` отправляется не более одного раза за стрим (`abortNotified`)
- **`ac.signal.aborted` проверяется явно** — в начале каждой итерации `while` и внутри `for (const line of lines)`: это позволяет остановиться немедленно, не дожидаясь пока `reader.read()` выбросит `AbortError` после дренажа внутреннего буфера `ReadableStream`

**Content** (`ApiClient.js`):
- `streamRequest` возвращает `{ abort }`; опциональный колбэк `onAbort(накопленныйТекст)`
- Флаг `isAborting`: устанавливается в `true` при вызове `abort()` ещё до подтверждения от background
  - входящие `chunk`-сообщения игнорируются (UI не дёргается пока идёт подтверждение)
  - если `done` приходит раньше `aborted` (гонка очередей), он трактуется как `aborted` → вызывается `onAbort()`, а не `onDone()`
- Таймаут по-прежнему закрывает порт и вызывает `onError` (не считается пользовательской отменой)

**UI**:
- Explain: одна кнопка переключается в режим «Стоп» (класс `codereview-explain-btn-stop` в `styles.css`)
- Review: отдельная кнопка `#review-stop-btn` в шапке окна

5. **UX**: Плавающие окна с drag&drop, resize, minimize, persist state; прерывание генерации LLM («Стоп») в окнах review и explain
6. **Performance**: Streaming responses, кеширование результатов
7. **Безопасность**: Изоляция content scripts, CSP, secure storage для API ключей
